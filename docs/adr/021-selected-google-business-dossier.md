# ADR 021: Automatic capture of a selected Google Maps business

Date: 2026-10-29

The user requested one button that opens a selected business in Google Maps, collects its displayed details, closes that window, and expands the existing search panel into a business dossier. This extends ADR 020's manual import workflow; the bounded polling described here replaces its no-polling decision only for an explicitly initiated selected-business operation.

Use the installed Tauri/WebView2 runtime and a fixed bundled script. Name normalization preserves Arabic and removes accent differences. Automatically choose a result only when one result matches the name and has nearby explicit listing coordinates or matching city text. Never use Google camera coordinates. A selected listing must also match its name and location. Duplicate branches, mismatches, consent, and verification require user recovery; FRIDAY does not pick the first result or close an unresolved window.

Poll only while this operation is active, for at most 50 seconds plus an in-flight callback bounded to four seconds. Capture two stable snapshots of contact/location/website/hours; allow a listing with no contact fields after four stable snapshots. Successful capture closes the research window and restores FRIDAY focus. Cancelling, changing selection, or hiding the panel closes its owned research window, and stale responses cannot replace another selection. Research windows retain Google-only navigation, denied popups, and denial of all FRIDAY application commands.

The existing aside expands using a 200ms transform/opacity transition. Independent ASCII field plates resolve in 200ms, rather than replacing the workspace with a skeleton. The pending operation has a framed seven-line ASCII loader. Reduced motion stops glyph changes and resolves the overlay immediately. No new dependency, background crawler, paid API, or subscription is added.

Imported fields remain source-backed candidates until the user confirms the business and branch. Saving records Google's URL, provider, and verification time; the existing website project flow receives those reviewed details. Missing fields remain unknown. Opening status is a capture-time observation rather than a guaranteed weekly schedule or current live status.

Live verification with Four Points by Sheraton Oran exposed a WebView2 startup race (`about:blank` before the requested page), an OSM-only leading `Hôtel`, and a translated identity heading. Startup is retried without importing the blank document; name matching tolerates the hotel descriptor; bilingual headings within one main landmark retain the primary identity. Google hotel pages also contain tenants and suggestions: telephone/address/website candidates use the listing's named information region, nested result cards are excluded, and broad main text is never used to infer opening status or phone numbers. The regression fixture includes the tenant's unrelated closed status and telephone number.

The user then requested photos. Capture up to six rendered images from a photo control explicitly naming the selected business, restricted to Google's photo CDN. The dossier displays source-linked images and an ASCII block until each image actually loads; failed or unavailable images fall back to the existing Commons/OSM source viewer. These are displayed research photos, not generated assets or automatically copied website assets. The user stopped Computer Use with physical Escape before final live acceptance, so further verification uses builds and source/isolation tests; final UI/photo rendering remains unverified this turn.

The user's dossier screenshot showed the heavy Archivo Black title treatment disrupting the interface. Business panel headings now use the existing Manrope interface face at weight 600; the surrounding OS typography remains intact.

Duplicate-name recovery now has an always-available **Capture selected listing** action after the research window opens, including while automatic research is running. This explicitly imports the listing the user chose, bypassing automatic name/location matching while retaining Google-only capture, selected-listing validation, source review, and window closure. Competing automatic/manual responses accept only the first result for the current window; cancellation invalidates both. Verbose selected-panel guidance was removed and secondary actions/research/evidence were moved into collapsed disclosures.
